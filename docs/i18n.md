# Localization (i18n)

Optional Russian localization, English staying the source language and the
default. Source files: `kf_lib/i18n/` (the engine, a leaf package — stdlib
only), `locale/ru/LC_MESSAGES/` (catalogs), `quotes/ru/` (translated quote
pools), `dev_scripts/i18n_*.py` + `translate_names.py` (catalog tooling).
Coverage as of 2026-09 (milestone 1): menus and meta UI, all fight text,
quote pools, all name catalogs (moves/techs/styles/items/traits/weapons/
group names), and `boosts.PMAP` descriptions. Not yet covered (milestone 2,
see BACKLOG.md): encounter/story/event prose, biographies, gossip, the stats
report, and the debug menu.

## Architecture

The game is translated through **two gettext domains**, both living in
`locale/<lang>/LC_MESSAGES/` (cwd-relative, like `quotes/` and `moves/`):

- `kfw` — prose / message templates, used via `_()` and `ngettext()`.
- `kfw_names` — name catalogs, used via `tr_name()` / `tr_style_name()` /
  `tr_fighter_name()`.

With language `'en'` everything is a `NullTranslations` pass-through, so the
English game is byte-identical to the pre-i18n one. Missing catalog entries
fall back to the English msgid, so catalogs can be filled and reviewed
incrementally. Compiled `.mo` files are committed (players need no gettext
tooling); `.po` sources sit next to them.

### Identifiers stay English; display names translate at render

Move/tech/style/item/trait names are dict keys (`ALL_MOVES_DICT`,
`all_styles`), save-file keys and ASCII-art lookup keys — they **never**
change. Translation happens in a display layer: `Move.display_name`,
`Tech.display_name`, `Item.display_name`, `Weapon.display_name`,
`Style.display_name` / `display_public_name`, and
`Fighter.get_displayed_style_name()` (which also routes through
`tr_style_name`). Any new user-facing print of such a name must go through
the display property, not `.name`.

Generated style names (`"W1 W2 W3"` and their public `"{W2} {W3}"` forms)
are **not** in the names catalog — `tr_style_name` reassembles them from
gendered Russian word data (`kf_lib/i18n/_ru_words.py: render_style_name`)
with adjective-noun gender agreement. This works because the generator's
word lists are closed (37 + 33 + 33 words); any new word added to
`style_gen.py` must also be added to `_ru_words.py` or the style renders in
English. The handcrafted style 'White Crane' intentionally matches the
W2+W3 shape and renders correctly through the same path.

`tr_fighter_name` translates the descriptive prefix of NPC names
('Beggar Wang' → 'Нищий Wang') and known group names ('Thug 1' →
'Головорез 1'); the generated proper-name parts stay as-is (Chinese-ish
syllables transliterate poorly and carry no meaning).

### Quotes

`actors/quotes.py` binds its pools at import time; `load_quotes` prefers
`quotes/<lang>/<file>` when the language is non-English and the file exists,
else the English file. `set_language()` reaches into `sys.modules` and calls
`quotes.reload_quotes()` if the module is already loaded, so language
switching works at any point (tests, dev scripts). A translated quote file
must preserve the line count of the English original — pools are picked by
`random.choice`, so a missing line just shrinks the pool, but the loader
splits on `'\n'` and a trailing newline creates an empty quote.

### Import-order constraint

Quotes, PMAP descriptions and some message templates are bound **at import
time**, so the language must be selected before content modules load:
`kfw.py` defers all `kf_lib` imports into `main()`, after
`i18n.set_language()`. Resolution order: `--lang` flag > `KFW_LANG` env var
> `'en'`. Consequence: `boosts.PMAP` descriptions are generated in whatever
language is active at import — switching language mid-process does not
regenerate already-built `Tech.descr` strings (fine in the real game, where
the language is fixed at startup; relevant in tests).

### Grammar helpers

`kf_lib/utils/_lang_tools.py` dispatches on language: `add_article` is a
no-op in Russian (no articles), `enum_words` joins with ' и ', `sg_or_pl`
returns `''`. Russian phrasing generally **avoids declension** rather than
computing it: messages are written so names and numbers sit in
case-neutral positions ('Урон: 5', not an inflected 'бьёт {name}а').

### Auto-coloring in Russian

`render()` (`ui/_rich_format.py`) colors systematic output patterns without
call-site markup (see `docs/ui.md`). Its English regexes match exact output
shapes (`lv.5`, `N coins`, `N exp`, `Round N`, `Day N`); when the language
is Russian an additional set of patterns (`_AUTO_COLOR_RES_RU`) matches the
translated shapes (ур.5, N монет, N опыта, Раунд/День N). **The Russian
message templates must produce exactly these shapes** or the auto-coloring
silently stops applying.

## Workflow for translators / developers

1. Wrap user-facing strings in `_()` (prose) or route names through the
   display layer. The extractor is AST-based and only sees **bare-name**
   calls: `from kf_lib.i18n import _` then `_(...)` — `i18n._(...)` is
   invisible to it (Attribute calls *are* matched for some name-harvest
   sites like `p.add_accompl('...')`, but prose must use the bare form).
2. Use named or positional placeholders and interpolate **after**
   translating: `_('You gain {} exp').format(n)`, never `_(f'...{n}...')` —
   f-string contents can't be extracted.
3. Use `ngettext(singular, plural, n)` where a count is in the sentence —
   Russian has three plural forms (1/2-4/5+; the `Plural-Forms` header in
   `kfw.po` handles it).
4. Regenerate catalogs: `cd dev_scripts && ../.venv/bin/python
   i18n_extract.py` (scans `kf_lib/` + `kfw.py`, harvests names from the
   content modules; never deletes existing translations).
5. Translate the empty `msgstr`s in `locale/ru/LC_MESSAGES/*.po`. For the
   names domain, `translate_names.py` machine-fills them deterministically
   from the compositional dictionary in `dev_scripts/_names_ru.py`
   (adjective genders + head nouns + possessive genitives + overrides) —
   meant as a draft for human review, and it never overwrites an existing
   `msgstr`. `fill_prose_ru.py` + `_prose_ru.py` did the same one-shot for
   the milestone-1 prose (kept for reference).
6. Compile: `cd dev_scripts && ../.venv/bin/python compile_locale.py`
   (pure-Python .po→.mo compiler in `i18n_common.py` — no gettext binary
   needed).
7. Check coverage: `cd dev_scripts && ../.venv/bin/python
   i18n_coverage.py` (extracted msgids vs translated msgstrs).
8. Verify: `.venv/bin/python -m pytest` (see `test/test_i18n.py`) and a
   manual `python kfw.py --lang ru` run; `python kfw.py --autoplay
   --lang ru --silent-ending` smoke-tests headlessly.
